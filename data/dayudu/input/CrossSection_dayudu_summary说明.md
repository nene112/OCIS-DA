# 大禹渡断面JSON整理说明

输入45条渠段记录完整保存到 `CrossSection_dayudu_summary.geojson`。该文件是严格JSON，采用参考文件的FeatureCollection/Feature/properties结构。一条记录表示一个桩号范围，不把渠段范围误当实测单点断面。

空白数值为null，原始13列均保存在source_values。桩号换算为米，纵坡1/n换算为数值。半径栏普通数字保留为radius_m，D前缀保留为diameter_m，原文均保留。

局部断面只对参数足够的矩形和梯形推导。梯形使用对称边坡、水平/垂直坡比的假设，并记录推导方法；弧底、U形、隧洞与缺测渐变段不虚构节点。倾角栏不重新解释为底宽。z_list是相对底高程，不是绝对床面高程。局部横坐标从最左端0开始。工程措施只保留原文，不将h+0.6自动叠加到现有渠高。

表中没有GIS坐标、绝对底高程与CRS，geometry及x/y/z为null。参考CrossSection.geojson包含其他案例的坐标和注释，未拷贝其坐标或覆盖原文件。

## 当前DLL读取入口

导出函数：`set_CrossSection(OcisMILPNetLab* obj, const char* CrossSection_path, int cs_start, int cs_end)`。
位置：`D:/Algorithm dev/0_MultiProj_OCISscip_proj/OcisMILPNet_dll/src/OcisMILPDll_export.cpp:3028`。
传入的是目录，函数扫描其中名称包含geojson的文件。cs_start/cs_end是有效断面记录的起止索引，包含两端。

调用链：set_CrossSection -> waterSediment::get_canal_CrossSection_fromGeojson -> LoadCrossSectionPoints -> SmoothAllCrossSections -> UpdateNodeZByCrossSection。

实际解析函数：`src/waterSediment.cpp:15353`的LoadCrossSectionPoints，只读取properties.canal、Name、river_distance和geometry.coordinates[0..2]。随后平滑高程，通过平面坐标邻近匹配将水动力节点zb更新，并保持h不变更新wh。当前没有读取z_list、cumulative_distances、底宽/边坡/圆弧等横断面形状参数。

因此整理出的文件可供检查和后续补充数据，但不能宣称现有DLL已经支持导入这45段横断面形状。直接调用入口还会WriteMesh写网格文件；此次未调用DLL入口、未修改源代码或已有DLL。

共26条记录生成了标明假设的局部断面节点。
